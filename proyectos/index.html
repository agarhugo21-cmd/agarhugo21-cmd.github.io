Práctica final · 10 triggers en MySQL
-- 1. Registrar cada cliente nuevo
CREATE TRIGGER insertar_cliente AFTER INSERT ON clientes FOR EACH ROW
BEGIN
  INSERT INTO auditoria_general (tabla_afectada, operacion, descripcion)
  VALUES ('clientes', 'insert', CONCAT('Se ha insertado el cliente: ', NEW.nombre));
END $

-- 2. Copiar el precio del producto al detalle del pedido
CREATE TRIGGER precio_producto BEFORE INSERT ON detalle_pedidos FOR EACH ROW
BEGIN
  SET NEW.precio_unitario = (SELECT precio FROM productos WHERE id_producto = NEW.id_producto);
END $

-- 3. Calcular el subtotal
CREATE TRIGGER subtotal BEFORE INSERT ON detalle_pedidos FOR EACH ROW
BEGIN
  SET NEW.subtotal = NEW.cantidad * NEW.precio_unitario;
END $

-- 4. Sumar la línea al total del pedido
CREATE TRIGGER actualizar_pedido AFTER INSERT ON detalle_pedidos FOR EACH ROW
BEGIN
  UPDATE pedidos SET total = total + NEW.subtotal WHERE id_pedido = NEW.id_pedido;
END $

-- 5. Descontar el stock vendido
CREATE TRIGGER actualizar_stock AFTER INSERT ON detalle_pedidos FOR EACH ROW
BEGIN
  UPDATE productos SET stock = stock - NEW.cantidad WHERE id_producto = NEW.id_producto;
END $

-- 6. Bloquear pedidos sin stock suficiente
CREATE TRIGGER comprobar_stock BEFORE INSERT ON detalle_pedidos FOR EACH ROW
BEGIN
  DECLARE stock_actual INT;
  SELECT stock INTO stock_actual FROM productos WHERE id_producto = NEW.id_producto;
  IF stock_actual < NEW.cantidad THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Stock insuficiente para realizar pedido';
  END IF;
END $

-- 7. Avisar cuando el stock baja del mínimo
CREATE TRIGGER aviso_stock_minimo AFTER UPDATE ON productos FOR EACH ROW
BEGIN
  IF NEW.stock < NEW.stock_minimo THEN
    INSERT INTO aviso_stock (id_producto, mensaje)
    VALUES (NEW.id_producto, CONCAT('El producto ', NEW.nombre, ' tiene stock bajo: ', NEW.stock));
  END IF;
END $

-- 8. Guardar el historial de precios
CREATE TRIGGER cambio_precio AFTER UPDATE ON productos FOR EACH ROW
BEGIN
  IF OLD.precio <> NEW.precio THEN
    INSERT INTO auditoria_precios (id_producto, precio_anterior, precio_nuevo, fecha_cambio)
    VALUES (NEW.id_producto, OLD.precio, NEW.precio, NOW());
  END IF;
END $

-- 9. Recalcular el total al borrar una línea
CREATE TRIGGER recalcular_pedido AFTER DELETE ON detalle_pedidos FOR EACH ROW
BEGIN
  UPDATE pedidos
     SET total = (SELECT IFNULL(SUM(subtotal), 0) FROM detalle_pedidos WHERE id_pedido = OLD.id_pedido)
   WHERE id_pedido = OLD.id_pedido;
END $

-- 10. Devolver el stock al borrar una línea
CREATE TRIGGER devolver_stock AFTER DELETE ON detalle_pedidos FOR EACH ROW
BEGIN
  UPDATE productos SET stock = stock + OLD.cantidad WHERE id_producto = OLD.id_producto;
END $
Empresa con 9 VLAN y OSPF

18 PCs · 3 switches

Red de una empresa con 9 departamentos (Compras, Ventas, RR. HH., IT, I+D, Marketing…) repartidos en tres switches multicapa Cisco 3560.

Qué configuré

  • 9 VLAN con enrutamiento inter-VLAN mediante SVI
  • Enlaces /30 entre switches con puertos enrutados
  • OSPF (área 0) para que todas las redes se vean
  • SSH v2 con usuario local para la gestión remota
  • ACL extendidas: bloqueo de TFTP/FTP, HTTP, SMTP y SNMP hacia rangos concretos de IP

MS1 · fragmento de la configuración

interface Vlan10
 ip address 192.168.10.254 255.255.255.0
 ip access-group ACL_1 in
router ospf 1
 router-id 1.1.1.1
 network 192.168.10.0 0.0.0.255 area 0
 network 192.168.100.0 0.0.0.3 area 0
ip access-list extended ACL_1
 ! TFTP y FTP de 192.168.10.2 a las 17 primeras IP de la 40
 deny udp host 192.168.10.2 192.168.40.0 0.0.0.15 eq tftp
 deny udp host 192.168.10.2 host 192.168.40.16 eq tftp
 deny tcp host 192.168.10.2 192.168.40.0 0.0.0.15 range 20 ftp
 deny tcp host 192.168.10.2 host 192.168.40.16 range 20 ftp
 permit ip any any
line vty 0 4
 login local
 transport input ssh

Dual-stack IPv4 + IPv6 con 12 VLAN

24 PCs · 4 switches

Cuatro switches multicapa en malla, cada uno con tres VLAN, y todo configurado a la vez en IPv4 e IPv6.

Qué configuré

  • 12 VLAN con enrutamiento inter-VLAN en IPv4 e IPv6
  • Seis enlaces /30 entre switches, también con su red IPv6
  • Enrutamiento estático IPv4 e IPv6 por el camino más corto
  • SSH en IPv4 e IPv6, permitido solo desde las redes de administración
  • ACL: se bloquea DNS, HTTP y Telnet de un equipo hacia una red

SM1 · fragmento de la configuración

ipv6 route 2001:DB8:ACAD:70::/64 2001:DB8:ACAD:170::2
ip access-list extended ACL1
 deny udp host 192.168.10.2 192.168.80.0 0.0.0.255 eq domain
 deny tcp host 192.168.10.2 192.168.80.0 0.0.0.255 eq www

Direccionamiento VLSM y router-on-a-stick

12 PCs · 3 routers · 3 switches

A partir de la red 172.10.0.0/16 calculé las subredes justas para cada VLAN y cada enlace, y monté la red con tres routers y tres switches multicapa.

Qué configuré

  • Cálculo VLSM: /24, /26, /28 y /30 según los equipos de cada red (cálculo incluido en PDF)
  • Router-on-a-stick con subinterfaces 802.1Q
  • Enrutamiento estático IPv4 e IPv6 entre los tres routers
  • SSH en IPv4 e IPv6

Diagnosticar y reparar una VPN IPsec

3 routers · 3 switches · 3 PCs

Tres sedes unidas por enlaces serie en las que la VPN entre sedes no funcionaba. Tuve que encontrar los fallos y corregirlos.

Qué configuré

  • Fallos encontrados: un router sin la VPN configurada y una política ISAKMP con el número equivocado
  • Parámetros que no coincidían: cifrado AES-256, grupo Diffie-Hellman y autenticación por clave compartida
  • Faltaban las rutas estáticas y un equipo tenía mal la IP
  • Resultado: túneles IPsec con ESP-AES + SHA-HMAC y ACL de tráfico interesante

Router central · fragmento de la configuración

crypto isakmp policy 10
 encr aes 256
 authentication pre-share
 group 5
crypto isakmp policy 20
 encr aes 256
 authentication pre-share
 group 2
crypto ipsec transform-set nombre2_p10 esp-aes esp-sha-hmac
crypto map nombre3_p10 10 ipsec-isakmp
 set peer 50.0.0.1
 set transform-set nombre2_p10
 match address 101
access-list 101 permit ip 192.168.20.0 0.0.0.255 192.168.10.0 0.0.0.255
ip route 192.168.10.0 255.255.255.0 50.0.0.1

Simulacro de examen de ciberseguridad

8 PCs · 8 dispositivos IoT · 6 switches · 4 portátiles · 4 servidores · 2 routers · 2 routers Wi-Fi · 1 cortafuegos ASA

Ejercicio completo que junta todo lo del trimestre: cortafuegos, VPN, Wi-Fi con AAA, IoT y seguridad en los puertos del switch.

Qué configuré

  • Cortafuegos Cisco ASA 5505: zona inside (nivel 100) y outside (nivel 0), con DHCP en cada una
  • VPN SSL sin cliente (WebVPN): cada usuario solo puede abrir su web
  • VPN IPsec entre las sedes de Administración y Técnicos
  • Wi-Fi con AAA e IoT con tarjetas RFID
  • Port security: MAC fija en un switch y MAC «sticky» en otro
